## 6. Irregularities and limits (flagged, not inferred)

- **Demo account disconnected.** `data/account.json` reports `connected: false`, `captured_at: null`. No demo credentials
  were configured or requested by this session, so no authenticated balance/position/fill read and no demo order was
  executed. Portfolio/strategy figures are the in-browser paper model, not Kalshi account results.
- **Scheduled-workflow cadence.** The alert engine declares a 10-minute cron, but GitHub documents that `schedule` runs can
  be delayed or dropped (see [GitHub scheduled workflow limits](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule));
  measured history shows multi-hour gaps. This is published as finding **F-83**. The keepalive pulse and the freshness
  badge make staleness visible rather than silent.
- **Static-page WebSocket.** The authenticated WebSocket stream is not used by the browser (confirmed above); live
  alerting is REST polling, which can miss moves between observations.
- **Stale-PR #100 superseded.** PR #100's unique file carried finding IDs that collide with `main`'s renumbered rows and
  a 2026-11-22 feed sample. Its substantive findings are already published on `main`; the content was integrated by
  `session-3dd2b218` with corrected IDs (see board). PR #100 is closed as superseded.
- **Model ROI is heuristic.** High-ROI labels and dollar-volume estimates are project calculations, not realized returns.
