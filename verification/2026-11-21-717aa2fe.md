## Findings and source corrections

### F-54 — series-list request was not a valid filter test

The earlier record linked from F-54 says a `GET /series` request with `series_ticker=KXDPWORLDTOUR&include_volume=true&limit=3` returned a full dump and concludes series-list filters are unreliable. The current official [Get Series List OpenAPI reference](https://docs.kalshi.com/api-reference/market/get-series-list.md) lists `category`, `tags`, `include_product_metadata`, `include_volume`, and `min_updated_ts`; it does **not** list `series_ticker` or `limit`. A response to that undocumented parameter combination cannot establish that a supported filter failed. F-54 now withdraws the API-defect conclusion pending a test using documented parameters. The earlier session record is retained as historical evidence and superseded by this correction.

### F-L4-01 — aggregate volume source corrected; reconciliation remains open

The official [Get Series docs](https://docs.kalshi.com/api-reference/market/get-series.md) specify `GET /series/{series_ticker}?include_volume=true`; the schema defines `volume_fp` as the total number of contracts traded across all events in the series. The official demo response for [`KXDPWORLDTOUR?include_volume=true`](https://external-api.demo.kalshi.co/trade-api/v2/series/KXDPWORLDTOUR?include_volume=true) returns `volume_fp: "8245802181.00"`.

A current [five-market sample](https://external-api.demo.kalshi.co/trade-api/v2/markets?series_ticker=KXDPWORLDTOUR&limit=5) returned `volume_fp` values `121809.09`, `112110.67`, `348906.19`, `104618.88`, and `258577.56`. It is not a full series census and does not reconcile the all-events aggregate. The flagged row now records the confirmed source semantics and leaves the full-market reconciliation open. The prior claims that the single-series endpoint lacks `volume_fp` and that a list-filter bug prevented re-location were incorrect.

### F-60 — `/events?category=` is not a documented filter

The official [Get Events OpenAPI reference](https://docs.kalshi.com/api-reference/events/get-events.md) lists `limit`, `cursor`, `with_nested_markets`, `with_milestones`, `status`, `series_ticker`, `tickers`, `min_close_ts`, and `min_updated_ts`; it does not list `category`. Therefore a previously recorded query using `category=Crypto` returning events with other categories does not demonstrate failure of a documented category filter. F-60 records this as an unsupported-query assumption, not an upstream API irregularity. Root F-01 is the browser-CORS limitation and does not substantiate the category-filter claim.

The same assertion appears in `templates/catalyst.tpl`, `assets/catalyst.js`, and `templates/strategylab.tpl`, which are owned by the completed K1/K2 scope of `session-7f90cf50`. Those files were not edited here. A correction request is recorded in `COORDINATION.md` and the uncertainty is published as F-60.
