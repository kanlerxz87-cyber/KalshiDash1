## Official documentation rechecked

Fetched on 2026-11-27 from Kalshi's official developer documentation:

- [Demo environment](https://docs.kalshi.com/getting_started/demo_env): confirms mock funds, separate demo credentials, the recommended REST root `https://external-api.demo.kalshi.co/trade-api/v2`, the supported REST alternative `https://demo-api.kalshi.co/trade-api/v2`, and both demo WebSocket URLs. Kalshi cautions that demo prices and behavior may not reflect real markets.
- [API environments and endpoints](https://docs.kalshi.com/getting_started/api_environments): independently confirms the same REST and WebSocket endpoints and that demo/prod credentials are separate.
- [Orderbook responses](https://docs.kalshi.com/getting_started/orderbook_responses): the orderbook is a point-in-time snapshot; it returns bid arrays with price and contract count; implied asks are complements. A REST orderbook response does not provide continuously streaming book updates.
- [WebSocket Quick Start](https://docs.kalshi.com/getting_started/quick_start_websockets): handshake authentication is required, even though public market-data channels need no additional channel-level authorization. The prior anonymous handshake probe is recorded at [`data/ws-probe.json`](../data/ws-probe.json) and [`verification/2026-11-27-528c51c9.md`](2026-11-27-528c51c9.md); it measured no anonymous upgrade on the recommended host and HTTP 401 on the supported legacy host. The dashboard therefore cannot claim anonymous demo-WebSocket streaming.
- [Create Order V2](https://docs.kalshi.com/api-reference/orders/create-order-v2), [Get Market](https://docs.kalshi.com/api-reference/market/get-market), and [Market Settlement](https://docs.kalshi.com/getting_started/market_settlement) are the official order/result/settlement references linked by the site. This session did not submit an order or make an authenticated request.

## Irregularities and limits

1. **Stale live feed (verified locally):** 290.2 minutes old versus the 45-minute threshold. No fresh exchange observation is claimed. Root cause/reliability concerns for scheduled workflow delivery are tracked in F-83. The page should remain labeled stale until a later successful run writes a new committed feed.
2. **No authenticated demo account:** account portfolio/execution are not enabled in this build. Adding a key to browser code or committing it would be unsafe. Account setup guidance describes an out-of-repository secret workflow; until intentionally configured, all private values remain blank.
3. **HighROI means model preference, not measured return.** The current 20 flags were judged by a heuristic; no validated profitability, tradeable fill, or actual return is established. F-94 records the score-composition issue and avoids an unbacktested model change.
4. **No anonymous WebSocket stream:** official authentication docs and anonymous probe results agree. Current experience uses scheduled captures/browser-side REST polling and freshness indicators, with network/CORS limitations; it should not be marketed as guaranteed tick-level real time.
5. **“Dollar volume” is estimated:** the site derives an estimate from volume and price; Kalshi does not publish the exact aggregate traded-dollar field implied by “highest dollar amount”. The site labels the estimate; do not present it as exchange-reported notional.
6. **Source gate is not full content verification:** every canonical table row has an approved publisher link, but the offline gate does not re-fetch every page/value. Static historical/sample data remain timestamped and traceable; values not verified stay blank/flagged.
7. **Culture had 0 open markets in the last captured snapshot.** This is an empty observed result for that capture, not a guarantee about current exchange state.

## Suggested next improvements (non-blocking)

- Add a server-side relay/worker for authenticated WebSocket streaming only after a secure key-management design is approved; never expose signing secrets to GitHub Pages JavaScript.
- Add an external health panel for last successful sampler run, scheduler lag, endpoint latency, and source age; keep the existing stale badge and make stale chats visibly historical.
- Backtest the highROI heuristic on out-of-sample, fee-aware fills before calling any score “ROI” or changing weights; preserve the current model's provenance and comparison history.
- Keep account-order execution behind explicit demo-only safeguards, dry-run controls, and an audit log. Until the account is configured, preserve disconnected/blank fields.
- Add more robust internal/external link and data-age checks to the release workflow; external URLs are currently not fetched by the offline internal-link checker.
