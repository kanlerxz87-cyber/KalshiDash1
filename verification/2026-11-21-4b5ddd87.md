## 1. Why the inherited PR was failing CI (reproduced before editing)

`site-qa` job [136979728447](https://github.com/kanlerxz87-cyber/KalshiDash1/actions/runs/44948084471/job/136979728447)
failed at step 15, **“Retained alerts are re-scored with the current model”**. GitHub's job API gives
the step list (`gh api repos/kanlerxz87-cyber/KalshiDash1/actions/jobs/136979728447`): steps 1–14
`success`, step 15 `failure`, steps 16–19 `skipped`. Raw logs could not be downloaded in this
environment (`results-receiver.actions.githubusercontent.com` EOF), so the failure was reproduced
locally instead of guessed:

```
$ git worktree add --detach /tmp/pr72 FETCH_HEAD      # PR head 8d54759
$ for i in 1..5; do node scripts/check_rescore_retained.mjs; done
run1 exit=0
run2 exit=0
run3 exit=0
run4 exit=1     ✗ prices, arrows, deltas and timestamps must be byte-identical after a re-score
run5 exit=0
```

Cause: the fixture stamped all three rows with `ISO(60)`; each call returns its own millisecond, and
`applySample()` sorts alerts newest-first, so an **ordered** fingerprint changed although no value
did. Fix: distinct fixture timestamps and a fingerprint compared by id. 25 consecutive runs now
pass (`failures=0/25`).

## 2. A second defect found in the inherited work (F-75)

The inherited re-score called `modelScore(..., sampleAgeSeconds: 0)` for every retained row. Six of
the 14 rows in `main`'s committed sample had been published **with** the model's one-hour age
penalty; recomputing them as if the quote were fresh doubled them:

| row | published (v1) | re-score as inherited | after this fix |
|---|---|---|---|
| `trade:KXBTCY-27JAN0100-B97500@1795288205` | 0.277 | 0.554 | **0.277** |
| `trade:KXBTCY-27JAN0100-B97500@1795287304` | 0.277 | 0.554 | **0.277** |
| `trade:KXBTCY-27JAN0100-B97500@1795286379` | 0.277 | 0.554 | **0.277** |
| `trade:KXBTCY-27JAN0100-B97500@1795285460` | 0.277 | 0.554 | **0.277** |
| `trade:KXPRESPERSON-28-VRAM@1795288509` | 0.2756 | 0.5512 | **0.2756** |
| `trade:KXBTCY-27JAN0100-B97500@1795284560` | 0.281 | 0.562 | **0.281** |

The stored quote behind each of those rows is unchanged, so the H1 penalty still applies. The fix
adds `age_penalised` to the model's output and re-applies it during a re-score; rows scored before
the field existed are reconstructed exactly (a stored score matching the halved candidate within
1e-4 is penalised; nothing is guessed). After the fix, re-scoring the committed feed changes only
the five rows whose swing was not executable, and leaves all six penalised rows untouched.
