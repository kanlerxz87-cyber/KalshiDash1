### 2.3 Root causes in `tools/live_engine.mjs`

1. **`meta.generated_at` overwritten before `collectResolutions()`:** `runOnce()` invoked `let next = applySample(state, { nowSeconds: now, ... })` before calling `collectResolutions(client, next, { maxSeries, log })`. Because `applySample()` unconditionally sets `next.meta.generated_at = new Date(nowSeconds * 1000).toISOString()`, `collectResolutions()` read `now` instead of the previous run's timestamp, collapsing `min_settled_ts` to `now - 900` (15 minutes). Under GitHub Actions' multi-hour cron cadence (F-83), settlements occurring more than 15 minutes before a run fell outside the window and were missed. Offline tests did not catch this because they called `collectResolutions()` directly on a pre-built state without running `applySample()` first.
2. **No direct ticker lookup for overdue, alerted, or early-closed markets:** Once a settlement missed a `min_settled_ts` window — or closed early under `can_close_early: true` while its cached `close_time` still sat in the future (e.g., `KXPGATOUR-THRC26-MPEN`, `close_time` `2026-12-06`, `expected_expiration_time` `2026-11-22`, actually closed `2026-11-23T19:54:03Z`) — subsequent runs never re-checked those tickers directly, leaving them stuck in `awaiting` with `status: "active"`.
3. **Slice consistency guard (`feed.resolutions` vs `feed.awaiting`):** `feed.json` previously sliced `next.resolutions.slice(0, 100)` while `awaitingResolutions()` excluded all `next.resolutions` (up to `MAX_RESOLUTIONS = 400`), which could trip `scripts/check_alerts.mjs` consistency check 6a once more than 100 settlements accumulated.

### 2.4 Fix implemented (`tools/live_engine.mjs`, `tools/check_resolution_logic_test.mjs`)

- Added `computeResolutionSince(prevState)` and called it in `runOnce()` **before** `applySample()` overwrites `meta.generated_at`, passing the explicit `since` window to `collectResolutions()`.
- Added `collectDirectResolutions(client, state, { openTickers, alreadyFound, nowSeconds, batchSize, maxTickers, log })`, using the documented unpaged plural-ticker endpoint `GET /markets?tickers=...` (no other filters) for alerted markets, tracked markets missing from the current `status=open` poll, and markets past `close_time` or `expected_expiration_time`. Finalized markets (`status === 'finalized' || 'settled'` with `result` in `yes|no|scalar`) are emitted as resolution rows carrying the exact plural-tickers `source_url`; non-finalized markets (e.g. `determined`, `closed`) remain pending and emit truthful status updates.
- Added `publishedResolutions(state, limit = 100)` so resolved alerted tickers are always retained inside `feed.resolutions`.
- Added offline regression tests in `tools/live_engine.mjs` (`--selftest`) and `tools/check_resolution_logic_test.mjs` covering the 5-hour cron gap overwrite, overdue gas settlement, early-closed golf settlement, non-finalized `determined` status update, deduplication against series results, and `publishedResolutions` slice consistency.
