## 3. Defects found and fixed in this session

### F-82 — "Settled at" was blank for every resolved event (data-completeness defect)
- **Reproduced:** 475/475 `settlement_ts` fields in `data/snapshot.json` are `null`; the resolved
  table on `categories/gas.html` has 100 rows and every "Settled at" cell is an em dash.
- **Root cause:** `scripts/fetch-snapshot.mjs` mapped `settlement_ts: ev.settlement_ts ?? null`
  on the settled-event object. The official `GET /events` response puts `settlement_ts` on the
  nested market, not the event (verified in §2.4).
- **Fix:** the settled-event market mapping now also stores `settlement_ts: m.settlement_ts ?? null`.
  `scripts/build-site.mjs` already rendered `r.ev.settlement_ts || r.m.settlement_ts`, so no
  template change was needed.
- **Regression test:** new `scripts/check-settlement-ts.mjs` (wired as `npm run test:settlement`
  and a `site-qa` step). It asserts the capture maps the field, the generator reads it, and then
  runs the **real** `build-site.mjs` in a scratch tree on a patched copy of the **real** snapshot:
  the generated `categories/gas.html` must contain `2026-11-16 14:32:51`. A negative control with a
  null field must still render a blank. Verified to **fail** on the pre-fix capture (1 failure) and
  pass after.
- **Published as** `flagged.html#F-82`.

### F-83 — published engine note cited an unmapped working ID (`F-A9`)
- **Reproduced:** `data/live/feed.json` and `state.json` carry
  `meta.data_reset_reason: "Clean restart at the F-A9 price-rule fix…"`, and the alerts console
  prints it as "Engine note". The flagged page's ID note mapped only F-A1…F-A8, so `F-A9` resolved
  to nothing.
- **Evidence it is F-49:** the 2026-11-20 commits that introduced the price-coherence rule are
  labelled `(F-A9)`; `docs/ALERTS.md` §5 states "A fifth and sixth pass then fixed the
  **price-coherence defect** (F-49) in four layers — reciprocity, stale-last-price, corroboration,
  and a clean state reset". The reset the note describes is that clean reset.
- **Fix:** the ID mapping note on `flagged.html` and in `EXECUTIVE_SUMMARY.md` now records
  **F-A9 → F-49**. The historical note text in the data is left untouched (it is the record).
- **Published as** `flagged.html#F-83`.

Both rows carry official source links and were regenerated into `flagged.html` by
`scripts/build-site.mjs`.

## 4. Irregularities and limitations observed (not fixed here)

1. **Scheduled sampling is unreliable (pre-existing, F-55/F-58).** `live-alerts`'s last
   `schedule` run was 2026-11-22T02:27:01Z; the feed was ~6 h old when this session started, and
   `keepalive`'s 15-minute cron (`4,19,34,49 * * * *`) last ran 2026-11-22T01:36:03Z. GitHub
   documents that scheduled runs are delayed or dropped under load. This is an infrastructure
   limitation, not a repository defect; the pages label the sample age honestly.
2. **Demo account is disconnected.** `data/account.json` has `connected: false` and
   `captured_at: null`; no `KALSHI_KEY_ID` / `KALSHI_PRIVATE_KEY` secrets are configured. The
   `demo-account` page states this. No authenticated read or order was attempted.
3. **Browser live polling depends on the visitor's network.** The CORS probe
   (`data/cors-probe.json`, F-01 resolved) measured that the demo API allows the GitHub Pages
   origin for public reads; the platform fetcher's own browser poll reported "request blocked", so
   the alerts console correctly fell back to the engine feed. Both paths are labelled at runtime.
4. **Contradictory demo quotes exist upstream** (F-49): e.g. the live `KXPRESPERSON-28-VRAM` row
   reads `last_price_dollars: 0.8020` against a `0.0020 / 0.0030` book. The site publishes the API
   value and flags the contradiction rather than correcting it.
