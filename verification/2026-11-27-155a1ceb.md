## Limitations / review flags

- A GitHub Pages static site cannot safely hold private API credentials. Personalized demo balance, positions, and real demo-account orders require a separate authenticated server or an explicit user-owned backend/secret setup; this audit did not enable account access or send orders. Existing paper/simulation tooling must not be represented as exchange execution.
- Live REST polling is sampled and can miss intra-poll price moves; WebSocket live streaming requires an authenticated handshake as already documented in the repo's measured WS probe. Do not describe the Pages snapshot as continuous live data.
- The committed snapshot is timestamped and finite, not a guaranteed current census. Rows with unavailable/unverified official values remain flagged/blank per existing convention.
- No new factual discrepancy was reproduced in this read-only audit. This does not constitute a live exchange-wide, row-by-row refresh of all historical market data. External links were not fetched by the internal-link checks.

## Suggested next improvements

1. For true personalized paper/live-account tracking, add an opt-in server-side demo adapter with credentials stored outside Pages, strict demo-host allowlisting, and no production fallback; retain read-only mode by default.
2. If true streaming is needed, proxy the Kalshi demo WebSocket through that backend and expose only sanitized public events to the browser; keep polling fallback and label feed age.
3. Surface last-success timestamp, stale-data warning, sampled-vs-streaming status, and source links consistently; continue retaining raw market and settlement endpoint provenance.
4. Keep simulated results explicitly separate from exchange fills and settlements; require independent strategy backtests before treating a model score as expected ROI.
