## C-1 · Get Trades — path is `GET /markets/trades` (not `/markets/{ticker}/trades`)

| Item | Verified value | Source |
|---|---|---|
| Endpoint path | `GET /markets/trades` (OpenAPI `get /markets/trades`) | [Get Trades](https://docs.kalshi.com/api-reference/market/get-trades.md) |
| Query params | `limit` (1–1000, default 100), `cursor`, `ticker` (filter), `min_ts`, `max_ts` (Unix **seconds**; millisecond values rejected with `400 bad_request`), `is_block_trade` | same |
| Response shape | `{ "trades": [Trade…], "cursor": "string" }`; empty `trades` (not 404) for unknown ticker | same |
| Trade fields (required) | `trade_id`, `ticker`, `count_fp`, `yes_price_dollars`, `no_price_dollars`, `taker_outcome_side` (`"yes"`/`"no"`), `taker_book_side`, `created_time`, `is_block_trade` | same |
| Legacy field | `taker_side` is deprecated; use `taker_outcome_side` / `taker_book_side` | [Order direction](https://docs.kalshi.com/getting_started/order_direction.md) |
| Demo server | `https://external-api.demo.kalshi.co/trade-api/v2` (listed in the endpoint's OpenAPI `servers`) | [Get Trades](https://docs.kalshi.com/api-reference/market/get-trades.md) |

Irregularity found: `GET /markets/{ticker}/trades` (per-market path) and the doc URL
`/api-reference/market/get-market-trades` do **not** exist — both returned fetch errors on
2026-11-20. Use `/markets/trades?ticker=…`. Earlier session notes referring to per-market trades
should be read with this correction.

## C-2 · Candlesticks — `period_interval` is minutes: 1 | 60 | 1440 only

| Item | Verified value | Source |
|---|---|---|
| Period values | "Time period length of each candlestick in minutes. Valid values: 1 (1 minute), 60 (1 hour), 1440 (1 day)." | [Get Market Candlesticks](https://docs.kalshi.com/api-reference/market/get-market-candlesticks.md) (summary in [llms.txt](https://docs.kalshi.com/llms.txt)) |

| Working URL shape (captured 2026-11-20T11:07Z) | `GET /series/{series_ticker}/markets/{ticker}/candlesticks?start_ts=…&end_ts=…&period_interval=1` | `dash/data/snapshot.json` → `candlesticks_sample.source_url` (verbatim capture from the demo API) |

in the browser/collector (already the root dashboard's approach) — do not request `period_interval`
values other than 1/60/1440.

## C-3 · Create order — exact contract (official quick start, demo host in the example)

| Item | Verified value | Source |
|---|---|---|
| Path | `POST /portfolio/events/orders` | [Quick Start: Create your first order](https://docs.kalshi.com/getting_started/quick_start_create_order.md) |
| Body (example fields) | `ticker`, `side: "bid"`, `count: "1"`, `price: "0.0100"`, `time_in_force: "good_till_canceled"`, `self_trade_prevention_type: "taker_at_cross"`, `client_order_id` (UUID4) | same |
| Auth headers | `KALSHI-ACCESS-KEY`, `KALSHI-ACCESS-SIGNATURE`, `KALSHI-ACCESS-TIMESTAMP`, `Content-Type: application/json` | same |
| Timestamp unit | **milliseconds** — `str(int(datetime.now().timestamp() * 1000))` | same |
| Signature input | `timestamp + METHOD + sign_path`, where `sign_path` is the full URL path from root, e.g. `/trade-api/v2/portfolio/events/orders` | same |
| Success | HTTP `201`; response contains `order_id`, `remaining_count`. "201 means accepted, not that it is resting" | same |
| `client_order_id` | optional but recommended; ≤64 chars from `A-Za-z0-9_-:+=/`; duplicate rejection is `409 order_already_exists` | same |
| Amend / cancel | `POST /portfolio/events/orders/{order_id}/amend`, `DELETE /portfolio/events/orders/{order_id}` | same ("Next Steps") |
| Errors | `400` (`invalid_price`, `insufficient_balance`, `invalid_order`), `401`, `404` (`insufficient_shard_balance`), `409` (`market_inactive`, paused), `429` | same; full list [Order Errors](https://docs.kalshi.com/getting_started/order_errors.md) |

Note on F-08 (prior flag: quick start uses legacy `side` while the order-direction page recommends
`outcome_side`/`book_side`): the **current official quick start** (read 2026-11-20) still posts
`side: "bid"`. `outcome_side`/`book_side` are documented for **Order/Fill/Trade responses**
([Order direction](https://docs.kalshi.com/getting_started/order_direction.md)). F-08 is refined,
not closed: order submission per the quick start is officially sourced; response-side field names
differ. Any implementation should post exactly the quick-start body.
