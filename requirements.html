Requirements check

One table for the brief this dashboard was built to. Each requirement says where it is delivered, what measures it, and the limitation that comes with it. A row is never marked done because a page mentions it: the “Checked by” cell names a test, a workflow or a dated verification record, and links it.

How to read this page. Delivered names the page or tool a trader actually uses. Checked by names the automated gate or dated record that would fail if it broke. Limitation is stated up front instead of being left for the trader to discover; every limitation here is also published on the Flagged for review page with its evidence. Values on the site are not restated here: they live in the tables on the page named, each with its own source link, so this page cannot drift out of agreement with them. Sources for the build itself are labelled, not overclaimed: a requirement that implements an exchange rule links that rule on Kalshi’s documentation; a requirement that is a project decision (which five topics, which model, which pages) links this repository’s own code and README instead, because no exchange document defines it. The source gate accepts both kinds and rejects an internal-only link pretending to be an official claim.

What this page deliberately does not do

It does not re-type any price, count or volume. Those live in the tables that carry their own source links, and duplicating them here would create a second copy that can silently disagree. It also does not grade itself: the “Checked by” column names the gate that would fail, so the claim can be re-run rather than trusted.
