Market Settlement https://docs.kalshi.com/getting_started/market_settlement On a YES outcome YES holders receive $1.00 per contract; on a NO outcome NO holders receive $1.00 per contract; only net positions are settled; settlement timing varies by market type; settlement fees are zero for simple yes/no determinations. Read in full on 2026-11-20. This is the rule the simulated portfolio settles against.
Market Lifecycle https://docs.kalshi.com/getting_started/market_lifecycle Statuses initialized, active, inactive, closed, determined, disputed, amended, finalized; result is yes, no or scalar; settlement_ts is populated once a market reaches finalized; the status= filter maps open->active, closed->any past close_time not yet finalized, settled->finalized. Read in full on 2026-11-20. Drives the resolution tracker.
Rate Limits and Tiers https://docs.kalshi.com/getting_started/rate_limits Token-bucket read/write budgets; most requests cost 10 tokens; unauthenticated public requests are subject to separate limits and callers should back off on 429. Read on 2026-11-20.

Rules this site follows

  1. Nothing is inferred. If a value cannot be confirmed from one of the sources above, the cell is left blank and the gap is listed on the Flagged for Review page.
  2. Every row carries its own provenance. Tables show the endpoint URL that produced the row, so a row can be re-fetched and compared directly.
  3. Documents and live payloads are both cited. Where the official documentation defines a field, the documentation is the source; where a row came from the demo exchange, the endpoint is the source.
  4. Derived values say so. Dollar columns, the ROI score and the swing alerts are derived by this project; each is labelled and its formula is published.

Data capture

The committed snapshot was produced by scripts/fetch-snapshot.mjs, which calls the public demo endpoints directly and stores each response together with the exact request URL. It uses 185 endpoint calls and covers 3386 open markets across the five focus topics. A GitHub Actions job (.github/workflows/refresh-data.yml) re-runs it on a schedule so the fallback data stays close to the live market.

To refresh it yourself on a machine that can reach the API: node scripts/fetch-snapshot.mjs. To rebuild the site from the templates: node scripts/build-site.mjs. To check internal links: node scripts/check-links.mjs.
