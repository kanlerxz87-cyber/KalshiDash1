1 · What was built

A single, static, dependency-free dashboard for Kalshi's official demo exchange, published on GitHub Pages. It ranks sampled live events in exactly the five requested topics — gas prices, elections, culture, crypto and golf — follows alerted markets toward resolution and turns observed price action into a live alerting system.

  • Two scrolling chats. The left pane posts every tracked contract that moves at least $0.10 in either direction. The right pane posts only the moves the published ROI model likes. Both carry the official settlement source that decides the outcome, so a swing can be investigated in one click.
  • Resolution tracking. Every contract this engine alerts on stays on a follow list until the exchange publishes result — yes, no or scalar — with its settlement_ts and settlement_value_dollars. Unanswered contracts are listed under Followed to resolution; answered ones move to the resolved table and to the resolution block on each market page. Both lists are read from the API, never inferred (see F-70 on Flagged for Review for the two retention/retrieval defects this replaced).
  • Price and liquidity. Gold markers and source-linked rows identify observed ≥ $0.10 changes; missing news causes stay unverified. Snapshot times are never relabelled as current. A time-series chart with selectable 30-second to 24-hour windows, a price axis, and an order-book ladder that answers "how many contracts are available at this price".
  • Simulated trading. Five project-authored strategies run automatically while a tab is open, using fresh observed asks with confirmed quantities. No fills are invented from a snapshot or a missing quote. They hold to final settlement and are grouped by strategy and topic. Gross P&L excludes fees, impact and legacy/unverified fills; no profitable ROI is claimed. See paper-model limits.
  • Demo-account access is not connected; do not enable it on this public site yet. A GitHub Actions job (tools/demo_trader.mjs) is designed to sign account reads with repository secrets and write data/account.json, but GitHub Pages serves that file publicly. If enabled now, balances, positions, fills and settlements would be published. The current snapshot remains connected: false with no capture time. Do not add account secrets until an access-controlled private data path is in place; see Flagged for Review F-85. The browser cannot sign requests itself because the demo API's preflight does not allow the three KALSHI-ACCESS-* headers (measured, F-66).

3 · Key verified facts

  • Public market data needs no authentication; only balances, positions and orders need signing. Market data
  • The demo endpoints in the brief match Kalshi's documentation exactly, and demo credentials are separate from production credentials. Demo environment
  • Markets resolve with yes, no or scalar. For a simple binary contract, a yes outcome pays YES holders $1 per contract and a no outcome pays NO holders $1 per contract. A scalar market pays the value it settles at (minus any settlement floor for YES), not a flat $1.00, so this site never prices a scalar contract as a binary win/loss — see F-84. Settlement · Settlement Bounds · Lifecycle
  • The WebSocket feed requires API-key authentication during the handshake — confirmed both by the official docs and by live anonymous handshake probes on 2026-11-27 (wss://demo-api.kalshi.co/trade-api/ws/v2 returned HTTP 301 → 401 token_authentication_failure; wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2 timed out after 10 s, see measured WS probe and probe record) — so a keyless static site must poll REST, and REST quotes can lag the exchange by a few seconds.   • Demo prices and behaviour may not reflect real markets, and demo funds are mock funds. Demo environment

4 · What it cannot show

  • Why a contract moved. The Kalshi API publishes no news feed. The chart links the published price observations, the event and separately labeled research sources. A settlement source is not evidence that it caused a move; verified causes stay blank.
  • Sub-minute history from the API. Candlestick periods are 1, 60 or 1440 minutes; seconds resolution exists only while a page is open.
  • A real portfolio without a key. The committed account snapshot says connected: false with no capture time; the demo-account page shows the demo-account snapshot that a GitHub Actions job produces from repository secrets. A browser cannot read the account itself: the demo host's CORS preflight does not allow the KALSHI-ACCESS-* headers a signed request needs (measured 2026-11-21 — F-66). Repository-secret configuration could not be enumerated by this integration token (403), so it is not asserted absent. In the current account snapshot no balance or account trade is verified: the portfolio figures are simulated and labelled as such, and data/account.json records connected: false.
  • A live order feed from the exchange. Kalshi's WebSocket handshake requires a signed API-key request (Quick Start: WebSockets; measured 2026-11-27 in data/ws-probe.json — anonymous_handshake_accepted_on_any_demo_host: false), so a static site cannot stream ticks. Alerts come from a scheduled REST sampler plus in-browser polling; the header badge always states the measured age of the newest sample.
  • Anything outside the five topics. The demo exchange lists many more categories; they are out of scope by the brief, and the full taxonomy is linked from API reference.

Every limitation is listed with its source on Flagged for Review.

5 · What a trader should do with it

  1. Open the dashboard and leave the left chat running. It is the cheapest way to notice a $0.10 move in a contract you care about.
  2. Use the right-hand pane to cut the noise: it only shows the contracts with liquidity, a tight spread and real volume.
  3. Open the contract, check the chart, the ladder and the settlement rules, and confirm the official source that decides it.
  4. View the simulated trades on the portfolio page; let the auto-trader run the published strategies and read the outcome on analysis.
  5. Check every number against the source link before acting. That is the point of the source column.
