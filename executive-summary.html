Executive summary

Prepared 2026-11-20. Each statement cites an official Kalshi source or is marked as unverified.

1. What was built

  • A static GitHub Pages site (no backend, no secrets). Live numbers are fetched in the visitor's browser from the official Kalshi demo Trade API.
  • Five category pages (gas prices, elections, culture, crypto, golf), a live price and liquidity dashboard, placeholder pages for portfolio and trading, a questions list, a suggestions list, a sources table and a Flagged for review page.

3. Key limitations

  • No dollar-volume field. The site ranks by open interest × $1 notional per contract (a derived figure). Raw volume in contracts is also shown. See F-03.
  • Seconds-level charts are not from the API. REST candlesticks start at 1 minute. Second-by-second points are recorded only while the dashboard is open in a browser. See F-02.
  • No portfolio, trades or P&L. Those need a demo API key and signed requests. None were provided and none were requested. See F-07.
  • Browser access is not confirmed. The sandbox could not run a browser against the demo API, so cross-origin access (CORS) is unconfirmed. If it fails, the pages say so. See F-01.

4. Decisions needed (choose on the Suggestions page)

  1. Whether to add a small server-side proxy (needed for signed portfolio calls and to avoid browser CORS limits).
  2. Whether to provide a demo API key through a secure channel for portfolio tracking. This is a user decision; nothing has been requested.
  3. Which trade categorisation schema to use before any trades are placed.
