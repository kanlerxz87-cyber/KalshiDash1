Your Kalshi demo account

Paste the credentials from your own Kalshi demo account and this page will read your balance, positions, fills and settlements straight from the demo exchange.

How your key is handled. The private key is imported into this browser tab with the Web Crypto API and held in memory only. It is never written to local storage, never included in a URL, and never sent anywhere except the Kalshi host you are connected to. Closing or reloading the tab discards it. Because this site is static and served from GitHub Pages, it cannot hold a server-side secret, so nothing is stored on your behalf.

1 · Get your demo credentials

  1. Log in at demo.kalshi.co.
  2. Open Account & security → API Keys and choose Create Key.
  3. Copy the API Key ID (a UUID) and download the Private Key (a PEM file).

Official guide: Quick Start: Authenticated Requests. Demo credentials work only against the demo endpoints, and demo funds are mock funds — demo environment.

2 · Load them in this tab

Requests are signed exactly as the official guide describes: base64(sign(timestamp + METHOD + path)) with RSA-PSS/SHA-256 or Ed25519, sent with the KALSHI-ACCESS-KEY, KALSHI-ACCESS-TIMESTAMP and KALSHI-ACCESS-SIGNATURE headers. The signed path excludes the query string.

What is and is not covered

  • Covered: GET /portfolio/balance, /portfolio/positions, /portfolio/fills and /portfolio/settlements against the demo host, signed in the browser.
  • Not covered: order placement. The API reference documents POST /portfolio/events/orders, but this site does not offer an order button, so a key pasted here can read your account and cannot spend it. That decision is recorded on the Flagged for Review page.
  • Not covered: the WebSocket feed, which requires API-key authentication during the handshake.
