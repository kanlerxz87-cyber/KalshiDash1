Trade Execution & Tracking

Execute trades on events, track performance, categorize trades, and build strategies by trade type. Demo environment uses mock funds.

Credentials required. Order placement is an authenticated endpoint (POST /portfolio/events/orders) needing a demo API key + Ed25519 private-key signature. No credentials were provided or requested, so execution is shown as a documented structure only.

Authenticated — not connected Order lifecycle (documented)

StepActionEndpoint (authenticated)Notes
1Find an open marketGET /markets?status=open (public)No auth needed; returns ticker, title, yes/no bid dollars.
2Place an orderPOST /portfolio/events/ordersFields: ticker, side (bid/ask), count, price, time_in_force, self_trade_prevention_type, client_order_id.
3Check order statusOrders endpoint (portfolio tag)Check remaining_count; 201 = accepted, not necessarily filled.
4Amend an orderPOST /portfolio/events/orders/{order_id}/amendAmend price or quantity.
5Cancel an orderDELETE /portfolio/events/orders/{order_id}Cancel resting order.
6Track to settlementGET /events/{event_ticker}Read result (“yes”/“no”) once status=settled.
Source: Quick Start: Create your first order (includes the full sign-and-post pattern and error codes: 401, 400, 404, 409, 429) · Order Errors · Market Settlement.

Example order payload (documented, not executed)

{
  "ticker": "KX...",
  "side": "bid",
  "count": "1",
  "price": "0.0100",
  "time_in_force": "good_till_canceled",
  "self_trade_prevention_type": "taker_at_cross",
  "client_order_id": "<uuid4>"
}

client_order_id (up to 64 chars: letters, digits, _ - : + = /) enables idempotent retries; resubmitting with the same ID while the order is open returns 409 order_already_exists.
