2. Authentication

  • Public endpoints (series, events, markets, orderbook, candlesticks, trades) need no credentials — Quick Start: Market Data (verified live against the demo host during this build).
  • Private endpoints (orders, portfolio, subaccounts) require three headers: KALSHI-ACCESS-KEY (key id), KALSHI-ACCESS-TIMESTAMP (ms), KALSHI-ACCESS-SIGNATURE (base64 signature of timestamp + METHOD + path, path without query string; RSA-PSS or Ed25519) — Quick Start: Authenticated Requests · API Keys.
  • WebSocket sessions are authenticated (same headers, signed path /trade-api/ws/v2) even for public channels — Quick Start: WebSockets.

6. Data model quick reference

Market fields this dashboard uses

  • status: initialized · inactive · active · closed · determined · disputed · amended · finalized
  • result: "yes" · "no" · "scalar" · "" (unsettled)
  • last_price_dollars, previous_price_dollars, yes_bid_dollars, yes_ask_dollars, no_bid_dollars, no_ask_dollars — fixed-point dollar strings (≤ 4 decimals)
  • yes_bid_size_fp, yes_ask_size_fp, volume_fp, volume_24h_fp, open_interest_fp — fixed-point counts (≤ 2 decimals)
  • notional_value_dollars ($1 for binary), settlement_value_dollars, settlement_ts, settlement_timer_seconds
  • price_ranges: per-market tick grid {start, end, step} — snap orders to it
  • Times: open_time, close_time, expected_expiration_time, latest_expiration_time

Sources: Get Market · Fixed-Point Representation

Rate limits (summary)

  • Authenticated traffic: token buckets per tier; most requests cost 10 tokens; Read/Write buckets separate; 429 on exhaustion with X-RateLimit-* headers, no cooldown penalty.
  • Unauthenticated public requests: separate (unpublished) limits — back off on 429.
  • Candlesticks: ≤ 5,000 periods per request; 1-minute candles ≈ 3.5 days per request.
  • This dashboard polls conservatively: topic lists every 2 min, selected market every 10 s, candles every 60 s, and pauses when the tab is hidden.

Source: Rate Limits and Tiers

7. Known API quirks (verified during this build)

QuirkWhat we observedImpact on this dashboardFlag
GET /events ignores unknown category param Requesting …/events?status=open&category=Crypto returned events of all categories (World, Elections…) instead of an error or filter. Matches the documented parameter list, which has no category filter. Topic filtering is done client-side via /series?category=… + series tickers — never via the events endpoint. F-01
No server-side volume ranking Get Markets ordering rules (documented) cover creation/close/settlement time only. Highest-dollar ranking is computed client-side per topic (series volumes → open markets → sort). F-03
Empty orderbook returns 200, not 404 Documented: a ticker with no book (or no such market) yields empty arrays. Ladder UI distinguishes "empty book" from "unknown ticker". —
