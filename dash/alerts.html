Live Alerts — swings ≥ $0.10, both directions

An alerting engine polls the tracked highest-dollar live markets of the five focus topics (gas · elections · culture · crypto · golf). Each 15 s cycle makes one batched GET /markets?tickers=… quote request (docs: a tickers-only request returns every matching market in one response) and additionally walks the most recent trades of the 4 highest-dollar tracked markets (Get Trades — each trade processed exactly once, so alerts carry exact trade timestamps). When a market's YES price moves ≥ $0.10, both chats get a row: the left chat logs every swing, the right chat only what the ROI model likes (score ≥ 70) plus every automated simulated trade it takes. Markets stay in the watch set until they resolve — resolution (yes/no) is logged from the API result field and settles open paper trades (see also Live Events).

ROI model ranking (watch set)

Two transparent models, both shown (no black box):
1. Four-component score (js/alerts.js, AlertsEngineCore.scoreMarket): score = 100 × (0.35·liquidity + 0.20·spread + 0.25·momentum + 0.20·band). Liquidity: log-scaled 24h dollar volume (contracts × $1 notional; $2,000 → 1.0, calibrated to the 2026-11-20 demo snapshot top rows). Spread: $0.01 → 1, $0.10 → 0 (prices tick $0.01, linear_cent, verified live). Momentum: largest observed move in the last 30 min ÷ $0.10 (warms up while the page polls). Band: mid-price $0.15–$0.85 → 1, falling to 0 near $0.02/$0.98. “Model likes” = score ≥ 70 — this gates chat 2 and the automated strategies.
2. Normalized ROI proxy (Alerts.modelScore, also used by the Automated Trading engine): 0.40·liquidity + 0.30·open interest + 0.30·opportunity, normalized against the current watch set; roiYes/roiNo estimate per-side return potential. Heuristic, not an official Kalshi model (F-09).
