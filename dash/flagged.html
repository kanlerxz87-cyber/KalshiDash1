F-01 GET /events silently ignores category query parameter Requesting open events with category=Crypto returned events from unrelated categories (World, Elections). The official parameter list for Get Events has no category filter, and the event category field is marked deprecated. Get Events docs · live probe (mixed results) Topic filtering relies on /series?category=… + series tickers instead. Two rows captured from this probe (KXNEXTNATOSECGEN-99-*) have partial fields and are marked where the response was truncated. Confirm the events endpoint should reject unknown params; consider reporting to Kalshi API feedback.

Reading that account requires the holder's demo API key + private key and signed requests. This session must never request or store credentials, so no real account data was read. demo_env.md · auth quick start All real-account figures (balance, positions, fills, real P&L) are blank. The Portfolio page is explicitly SIMULATED with seeded demo rows tagged seed. Provide demo keys locally via scripts/fetch_snapshot.mjs (see README) to populate real data — then re-verify (proposal S-01).
F-03 No volume-sorted market listing in the Trade API Get Markets ordering rules are creation/close/settlement time. "Highest dollar amount" ranking therefore cannot be fetched as a single server-sorted list. Get Markets docs The exact "top N by dollar volume across all markets" list is approximated by topic (series volume → open markets → sort). A scanner job (S-03) would make it exact. Confirm the ranking definition (24h vs total vs open interest) and whether a scheduled scanner is acceptable.

If it shows SNAPSHOT mode, use scripts/local-proxy.mjs locally or the S-03 scanner.

Blank-value policy

When a value could not be confirmed from an official source it is displayed as empty/“—” and listed above. No number on this site was copied from memory, guessed, or interpolated. Prices shown to 4 decimals and counts to 2 decimals follow the fixed-point conventions in Fixed-Point Representation.
