E. Alerting & automated trading

QuestionKnown (verified)MissingHow to discover it
How are ≥ $0.10 price swings detected? Answered Trade-by-trade prices from the public GET /markets/trades endpoint are polled at 10-second cadence; a swing ≥ $0.10 between observed prices fires an alert in both chats. Fallback: last_price_dollars polling. Offline: verified snapshot trades are replayed through the same detector. source — —
Can the alert latency be tighter? Partial REST responses are cached and lag the exchange; WebSocket needs an authenticated session (impossible from a browser without keys). source Sub-second freshness without keys. Server-side scanner (S-09) or authenticated WS bridge (S-02) — both need a runner with keys or a hosted cron.
What does the high-ROI model actually do? Answered A transparent heuristic: 40% liquidity (24h volume, normalized), 30% open interest (normalized), 30% opportunity (|0.5 − price| × 2). ROI proxy = (1−price) for YES, price for NO, scaled by liquidity. Markets scoring ≥ 0.50 pass the filter. Not a Kalshi feature — flagged F-09. source — (weighting is a design choice, reviewable). Adjust weights on the Alerts page after reviewing the formula.
Do the automated trades execute on Kalshi? Open No — they are simulated in-browser against live public prices. Real execution needs the account holder's demo API keys and signed POST /portfolio/events/orders requests, which this static site must never handle. source Demo account credentials (holder-provided, never requested by this session). Run a local signed runner (S-01) to execute and sync real fills.
How are positions settled? Answered Open simulated positions are settled when their market's result becomes yes or no; winning contracts pay $1 (settlement_value_dollars for YES holders). source — —
