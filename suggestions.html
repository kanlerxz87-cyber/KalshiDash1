Suggestions

How to make the dashboard more live, more interactive and more useful for a trader deciding on a contract. Each proposal says what it changes, why it matters, and which official source it rests on.

Already built into this site

SuggestionWhat it doesWhy it matters
Two scrolling chat panes One pane posts every move ≥ $0.10, the other posts only the moves the ROI model likes. Both scroll, filter by topic and direction, and can be paused. A trader watches a screen instead of a table. The split keeps signal and noise apart instead of hiding the noise.
Resolution announcements When a tracked market is determined, the chat posts the result — yes or no — with the settlement source. The brief asks to follow events until they resolve; the answer belongs in the same stream as the price moves.
Candidate source links Every swing message links the market page, the event's official settlement source and the exact API row. One click from "something moved" to the page that decides the outcome.
Time-window chart 30 s, 1 min, 5 min, 15 min, 1 h, 6 h and 24 h windows on the same chart, with the alert threshold drawn in. The brief asks for a time axis with a selectable span and a price axis; the threshold line shows at a glance whether a move would have triggered an alert.
Order-book ladder Contracts available at each price on both sides, with a depth bar. Answers "how many contracts are available at a given price" directly, and feeds the depth term of the ROI score.
Simulated strategy engine Five published strategies run automatically against live prices, settle on resolution, and are ranked by result. Turns a tracker into something that produces testable strategies instead of just showing prices.
Topic isolation Each topic has its own page with its series, open markets, liquidity and resolved events, and the topic pages are linked from the navigation. The brief asks to keep topics separate while keeping events grouped inside a topic.
Self-refreshing data A GitHub Actions job re-captures the demo snapshot on a schedule, so the fallback data never drifts far from the market. A static site needs a live snapshot to stay useful when the browser cannot reach the API.

What would make the charts simpler, not busier

  • One number per chart — the current price and the change — with the axis doing the rest. No dual axes, no gauges.
  • The threshold drawn as a single dashed line so "is this an alert?" is a glance, not a calculation.
  • Sparklines in the tables instead of full charts: the full chart belongs on the market page only.
  • Colour used only for direction and for status, so a green bar always means the same thing.
  • Every chart captioned with the endpoint and the window it came from, so a reader can reproduce it.
