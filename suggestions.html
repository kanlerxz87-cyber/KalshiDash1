Decision-making suggestions (choose the best path before implementing)

  1. Confirm demo-environment categories first. Before building category-specific discovery, verify whether gas/elections/culture/crypto/golf markets exist in the demo (they were not present at review time — demo listed sports markets). If absent, either use production markets (with appropriate disclaimers) or keep the category pages as discovery scaffolding.
  2. Decide on authentication model. Browser-side Ed25519 signing keeps keys on the client but requires careful key handling; a server proxy keeps keys off the client but introduces hosting/ops. Pick one before implementing portfolio/trade execution.
  3. Pick a single data source for prices. REST poll vs WebSocket vs both. WebSocket gives live movement; REST is simpler and documented as cached. Decide based on how real-time the graph must be.
  4. Set a verification rule for every table row. Keep the current rule: source link to an official site; blank + unverified if not confirmed. Never infer values.
  5. Validate the graph-time interpretation. The API offers 1/60/1440-minute candles (no sub-minute). Decide whether “seconds” means a seconds-long lookback at 1-minute resolution, and document that clearly (done on the dashboard).
