Strategies and the ROI model

Every rule that produces a simulated trade, and every term of the score that filters the high-ROI chat pane, written out so it can be recomputed from the same public API fields.

The project-authored paper model buys at the observed YES ask or NO ask, never at a bid or an assumed last price. It requires enough published quantity for the whole order and a local observation no older than 15 seconds. NO ask quantity equals the complementary YES bid quantity. Missing, stale, inactive or contradictory quotes cannot create a fill. Position size defaults to 10 contracts; project caps are 50 open positions and $1,000 open entry cost, not an account balance. All strategies hold to finalized. Gross results ignore trading fees, queue position, impact and latency; none of these rules has a validated ROI estimate. The ROI score

The score used by the right-hand chat pane is a weighted sum of five normalised components. Every component is between 0 and 1 and is derived from fields the Kalshi API returns, so any reader can recompute it.

ComponentWeightDefinitionSource fieldsOfficial field semantics (not the weights)
Liquidity0.26min(1, (yes_bid_size_fp + yes_ask_size_fp) / 300) — contracts resting at the best prices.yes_bid_size_fp, yes_ask_size_fpAPI definitions
Depth0.16min(1, total_contracts_in_book / 1200) across both sides of the order book.GET /markets/{ticker}/orderbookAPI definitions
Tightness0.221 − min(1, spread / 0.10) where spread is yes_ask − yes_bid; a missing touch scores 0.25.yes_bid_dollars, yes_ask_dollarsAPI definitions
Volume0.14min(1, volume_24h_fp / 20000) — contracts traded in 24 hours.volume_24h_fpAPI definitions
Volatility0.22min(1, |Δprice| / 0.30) over the last observed interval.consecutive last_price_dollars observationsAPI definitions

Score = 100 × (0.26·liquidity + 0.16·depth + 0.22·tightness + 0.14·volume + 0.22·volatility).

The high-ROI chat pane posts a move when this score is at least the filter value shown on the dashboard toolbar (default 55). The score is a ranking heuristic, not a recommendation: it measures how tradable a contract looks right now, not whether it will pay off.

How a new strategy is added

  1. Write the rule as a threshold on fields the API already returns — no hidden state, no look-ahead.
  2. Add it to STRATEGIES in assets/app.js with its exact wording, so the same text appears in the simulator and on this page.
  3. Let the auto-trader run it, then read its row on the analysis page.
  4. Compare it against the other strategies on win rate, total P&L and average trade, and keep or drop it.

The simulator is honest about its limits: it fills at the touch it can see, ignores trading fees, and settles only at exchange finalization with a binary result. It cannot run after the tab closes. Those limitations are listed on the Flagged for Review page.
