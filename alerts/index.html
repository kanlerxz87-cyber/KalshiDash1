Live alerts — two scrolling feeds

Every time a contract in gas prices, elections, culture, crypto or golf moves by $0.10 or more in either direction, it appears in the All events feed. The High-ROI feed repeats only the alerts that a documented heuristic scores at or above 0.62. Both feeds scroll in real time and keep working when the page is reloaded, because the engine also runs without a browser open.

How an alert is produced

  1. Discovery. The engine reads GET /series for each topic (Get Series List) and checks every category and tag it uses against the live tag taxonomy (/search/tags_by_categories). A tag missing from a category that publishes tags fails the run loudly instead of quietly showing an empty table. A category the taxonomy does not key at all (the demo has one — see F-A1) is recorded as a note and re-checked through discovery.
  2. Sampling. Open markets are read with GET /markets?series_ticker=…&status=open (Get Markets). The tracked price is the last traded price; if there is none, the midpoint of the yes bid and yes ask — and if the book has no real price on both sides, the market is skipped and counted, never guessed.
  3. Candles. The engine also reads 1-minute candles (Get Market Candlesticks) so a swing that happened entirely between two runs is still reported: an up-swing is close − low ≥ $0.10, a down-swing is high − close ≥ $0.10, using only periods that actually traded. Those rows are marked candle.
  4. Comparison. Each new sample is compared with the previous sample for the same contract, or, for 30 minutes after an alert, with that alert's price — so a slow grind alerts once, not on every sample.
  5. Resolution. Tracked contracts are re-read until they settle, and their result (yes / no) is recorded with the settlement timestamp (Market Lifecycle). Winning contracts pay $1 (Market Settlement).

What the high-ROI score means (and what it does not)

The score is a transparent heuristic, not a back-tested or fitted model. It never predicts an outcome; it ranks how tradable a $0.10 move looks from the fields the API publishes. Weights:

WeightTermHow it is computedWhy
0.20Headroommin(price_before, 1 − price_before) / 0.50A move near $0.50 leaves room in both directions; near $0.02 it is mostly noise.
0.20Move size|delta| / 0.50, capped at 1Bigger moves are bigger signals.
0.35Liquiditymin(1, volume_24h_fp / 1000)A move on an empty book cannot be traded, so it is not a high-ROI signal. Largest weight.
0.25Spreadmax(0, 1 − (yes_ask − yes_bid) × 10)A penny-wide book is cheap to enter and exit; a $0.10 spread eats the move.
×0.5Stalenessapplied when the sample is over an hour oldREST market data is cached and can lag the exchange.

Score = weighted sum in [0, 1]; highROI means score ≥ 0.62. Every row shows its own term values under “model terms”, so you can disagree with the ranking and see why. Nothing here is financial advice, and the demo environment uses mock funds whose prices “may not be reflective of those in real markets” (demo environment).

Data sources and limits

Engine feed: data/live/feed.json, written by tools/live_engine.mjs on a GitHub Actions schedule.

Browser polling: the page also calls the public demo API directly (https://external-api.demo.kalshi.co/trade-api/v2, demo environment). If your browser is not allowed to make that cross-origin request, the page says so and keeps using the engine feed instead of failing.

Public data only. No API key is used, requested or stored anywhere on this site; orders are not placed from the browser (that needs request signing — authenticated requests). Simulated trading lives under Portfolio.

Rate limits: unauthenticated public requests have their own limits and the documented reaction is to back off on 429 (Rate Limits); the engine implements exponential backoff and sleeps between requests.
