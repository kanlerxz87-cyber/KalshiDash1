Executive summary

Every factual claim below is sourced. The full line-by-line verification table is on the Sources page; anything that could not be confirmed is on the Flagged for Review page and is not stated as fact here.

1. What this project is

KalshiDash1 is a live, interactive dashboard that tracks the highest-dollar open events on Kalshi’s demo environment, restricted to five topics: gas prices, elections, culture, crypto, and golf. It follows each tracked event until it resolves, records whether it resolved YES or NO, tracks portfolio performance, categorizes trades, supports trade execution, and charts price movements with liquidity (orderbook depth).

It is a static GitHub Pages site (no server, no build step). Live market data is fetched directly in the visitor’s browser from Kalshi’s public demo API, so prices are always current — or the page explicitly says it cannot reach the API. No prices are ever hard-coded.

3. How “highest dollar amount” is defined

Kalshi’s public API does not publish a single “dollar amount” per event. Markets expose volume_fp (contracts traded) and price fields. This dashboard therefore ranks by a transparent estimate: estimated traded notional = volume × last price, shown alongside raw volume and open interest so the estimate can be audited. The estimate is labeled as an estimate everywhere it appears. See Methodology and Flagged F-05.

4. What the dashboard does

Live tracking

  • Discovers series for the 5 categories live from GET /series (no hard-coded tickers).
  • Ranks open markets by estimated notional; click a row for chart + orderbook.
  • Follows events until status = settled, then shows the API result (YES/NO).

Price chart & liquidity

  • X = time (60s, 5m, 15m, 1h, 6h, 24h, 7d), Y = contract price ($0–$1).
  • Orderbook table: contracts available at each price, cumulative depth, notional per level.
  • Best bid/ask derived using the binary equivalence (YES bid X ⇔ NO ask 100−X).

Portfolio & trading

  • Simulator (works with zero setup): local paper portfolio, $1,000 starting cash (configurable assumption, labeled as such).
  • Demo account (optional connect): balance, positions, fills via signed requests; key stays in the browser.
  • Trade execution in both modes; demo orders use the official V2 order endpoint.

Analysis & strategies

  • Trades categorized by category, side, and price bucket; stats per category.
  • Strategy backtests run locally on real candlesticks (educational, not advice).
  • Suggestions page for reviewing improvements and choosing a path; Open Questions page lists missing information.

5. Key limitations (read before deciding)

  • Demo ≠ real: “The price and behavior of markets in the demo environment may not be reflective of those in real markets.” (source)
  • No demo credentials were provided with this task, so the live demo portfolio starts empty until a user connects a demo API key in the browser. The simulator is fully functional meanwhile. See Open Questions Q-01.
  • Browser CORS for the demo API could not be confirmed from the build environment; the site handles failure explicitly. See Flagged F-01.
  • REST data is cached by Kalshi for a short time and can lag the exchange by seconds; WebSockets are recommended for current state. (source)
  • Nothing here is financial advice. Backtests are illustrations on past prices.
