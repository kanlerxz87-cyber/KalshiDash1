F-03Two different status vocabularies: the status filter accepts unopened | open | paused | closed | settled, while the Market.status response field is documented as initialized | inactive | active | closed | determined | disputed | amended | finalized — “settled” is not in the response enum.Get Markets (MarketStatusQuery vs Market.status)Resolution logic cannot rely on status === "settled" in responses.Resolution is taken from result first, with settled/finalized as a secondary signal; the raw status string is always displayed so a reviewer can see what the API actually returned.
F-12A docs page links to /api-reference/market/get-market-order-book while the order-book page is published at /api-reference/market/get-market-orderbook.Market Data quick start (Step 3 link)Anchors in our own pages must point at the working slug.All our links use get-market-orderbook; we did not rely on the mismatched slug.
F-13Deprecation dates overlap: legacy action/side “will not be removed before May 28, 2026”, a date already in the past today, while the V2 docs describe the legacy write endpoints as already removed (410 Gone).Order direction · Create Order (V2)Reading fills/orders by legacy fields may break silently.The site writes only the V2 shape and reads direction from outcome_side/book_side where present, falling back to display of whatever the API returned.
