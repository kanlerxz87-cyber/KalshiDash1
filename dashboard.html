Live alert dashboard

Two scrolling chats. The left pane posts observed tracked-contract changes of at least $0.10 in either direction, with the official sources that decide the outcome. The right pane posts only the moves the ROI model likes. Final binary resolution announcements appear after an API poll observes finalized. Polling can miss intervening moves; the first live read establishes a baseline, not a snapshot-to-now alert.

What the two panes contain

Left pane — all events

Every tracked contract whose reference price (last traded price, or the mid of the touch when there is no trade) moves by at least the threshold in one poll. Each message carries the time, the topic, the direction, the old and new price, the ROI score and links to:

  • the Kalshi market page for that contract;
  • the official settlement source the exchange itself names for the event — for example AAA for the gas series, the Texas Secretary of State for election series, as named in each series record (the Texas Secretary of State is the example the registry cites);
  • the exact API endpoint the row was read from.

The Kalshi API publishes no news feed, so settlement/research links are context, not proof of a cause. That limitation is listed on the Flagged for Review page.

Right pane — high ROI only

The same messages, filtered to the contracts whose ROI score clears the filter shown in the toolbar. The score rewards liquidity at the touch, depth in the book, a tight spread, real 24-hour volume and enough recent movement to be worth acting on. Captured replays, old unverified scores and unconfirmed/empty touches are excluded from this pane even if the numerical filter is 0. See the published eligibility gate.

Scoring is fully deterministic and published on Strategies, so a reader can recompute any score from the same public fields.

How the feed gets its data

  • Discovery: GET /series?category=…&tags=…&include_volume=true for each topic, then GET /markets?series_ticker=…&status=open.
  • Refresh: GET /markets?tickers=… in batches of 40 tickers, every few seconds.
  • Detail: GET /markets/{ticker}/orderbook?depth=20 for the liquidity ladder.
  • The WebSocket feed is not used: the official WebSocket connection requires API-key authentication even for public channels, so a keyless static site polls REST. REST responses are cached server-side for a few seconds, so a quote can lag the exchange slightly.
